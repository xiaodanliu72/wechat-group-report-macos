发布准备日期：2026-09-28。此文只包含脱敏验证结论；不随仓库提供真实聊天、账号、群 ID、数据库、密钥或本机原始运行记录。

## v0.2.0 版式迭代验证

- 本机共 35 项自动测试通过；新增覆盖恶意 HTML 文本转义、完整跨日时间、引用与阅读覆盖校验、未完成状态不误标完成、空窗口、默认八文件输出。
- 单个超长任务分图测试确认正文完整保留，PNG 每图高度不超过 12000 像素，并带页码。
- 虚构报告在 1440、390、320px 宽度下无横向溢出；来源默认折叠且可展开；无脚本或远程资源请求依赖。
- 虚构 PNG 与既有真实报告重新排版的 PNG 均人工查看，检查中文、正文中段及完整底部。此次迭代没有重新读取微信，不作为新增真实读取或新版本客户端兼容证据。
- 新版将标题等纯展示配置与报告事实分离；重要结论的语义是否被原消息支持，仍须当前智能体逐条核对，程序的引用存在性校验不能替代语义审核。

## 虚构报告

样例含 8 条消息、3 位虚构发言人；专门区分建议与决定、收到与同意、认领与完成，并包含链接卡片和未解析图片。虚构结果明确标记，不作为真实微信读取证据。HTML/PNG 渲染逻辑已在本机检查中文、完整底部、折叠来源、桌面及 390px 手机宽度；核心展示无远程资源。

## 本人真实账号的先前验证

同一台 Apple Silicon Mac，macOS 27.0，微信 4.1.13，Python 3.14.5、SQLCipher 4.19.0：

- 指定完整群名唯一匹配，联系人与必要消息库的密钥通过页 HMAC 与数据库完整性校验。
- 导出窗口按 SQL 计数核对，发送人映射、稳定消息 ID、消息排序和去重通过；当前智能体读完消息后生成实际 HTML/PNG/Markdown 报告。
- 一次明确授权的初始化将密钥保存到本机项目专用、不同步的 login Keychain，并回读核对。
- 原版恢复后连续三次使用钥匙串读取成功，未启动第二个微信进程，原版 PID 不变。用户在前两次后确认正常、没有掉线。PID 不变本身不能证明登录态正常。
- 这三次窗口内未出现新增消息，尚未证明新增消息、新分片或密钥变化场景。

## 尚未验证

没有第二台电脑、其他用户账号、Intel Mac、Rosetta、其他 macOS 或微信版本的现场验收。没有端到端压力测试任意大小数据库或证明手机历史已全部同步。SIGKILL/断电不能保证临时目录即时清理。

首次初始化的会话切换影响仍然存在，日常复用不会消除初始化的这一限制。项目使用系统 sandbox-exec、旧式文件 Keychain 及微信内部表结构，系统或客户端更新后可能失效；失败应停止并核查，不能为兼容而跳过加密、隔离或一致性校验。
